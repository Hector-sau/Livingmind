# 3 分钟演示讲稿

面向答辩现场。数据全部为设计的模拟数据，设备为后端虚拟设备。

## 上台前（1 分钟内）

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 后端：`LIVINGMIND_DEMO_LOCAL_HOUR=20 uvicorn app.main:app --host 0.0.0.0 --port 8000` | 能源建议固定在高峰电价时段 |
| 2 | App 打开，“我的”页点 **准备演示** | 林悦、舒适优先、设备 80% / 26°C / 100%、对话清空、回到对话页；提示 3 秒后消失 |
| 3 | 需要讲模型时确认后端 `.env` 已配置 DeepSeek；网络不稳就用“规则”模式 | 计划来源会如实标注 |

## 讲解顺序

| 时间 | 画面 | 讲什么 |
|---|---|---|
| 0:00–0:20 | 对话页空态 | LivingMind 是一个会“先说清楚再动手”的家庭空间助手；每位成员有自己的偏好 |
| 0:20–0:45 | 输入“我想休息”，出现计划卡 | 设备还没变；计划卡写明来源（规则 / 模型 / 规则降级）、能源建议和整晚安排；点“查看协作过程” |
| 0:45–1:10 | 协作过程展开 | 1+2 Agent：主 Agent 用规则路由与编排；Experience Agent 可调用大模型，超出偏离上限就降级；Space Execution Agent 用规则生成设备动作和整晚安排；Harness 执行前做安全与并发检查 |
| 1:10–1:30 | 点确认，结果卡 + 右侧设备变化 | 设备只经执行器写入，写完回读；服务状态条出现，显示模拟时间 22:30 |
| 1:30–1:45 | 点“模拟室温” | 室温升高 3°C，服务自动调空调一次（冷却 30 秒、最多 3 次、不超出偏好 ±3°C） |
| 1:45–2:15 | 点“自动播放整晚” | 同一个服务贯穿整晚：23:00 关灯、01:00 空调调高 1°C、06:30 起分三步唤醒；07:00 服务自动结束。时钟是模拟的，每一步只执行一次 |
| 2:15–2:30 | 输入“把空调调到24度” | 简单设备指令走简化分支，不开休息服务 |
| 2:30–2:45 | “我的”页 → 切换到陈川（PIN 1357） | 只能看到本人偏好；访客模式不读取任何个人偏好 |
| 2:45–3:00 | “场景”页 | 三个场景都已实现且标注了验证方式（真机未验证）；点开“起床渐进唤醒”看刚才的时间线 |

## 被问到时

| 问题 | 回答要点 |
|---|---|
| 三个都是大模型吗 | 不是。只有 Experience Agent 调用模型；主 Agent 与 Space Execution Agent 是规则实现，保证可控 |
| 模型失败怎么办 | 超时、格式错误、偏离上限都降级为规则计划，并在计划卡上写明原因 |
| 能省多少电 | 不给百分比。能源模块按分时电价和舒适范围给建议，负荷是规则估算 |
| 是真实设备吗 | 是后端虚拟设备，接口按真实适配器边界设计 |
| 整晚是真的等一晚上吗 | 不是。整晚安排跑在模拟时钟上，由按钮推进，便于演示和测试；真实部署时换成定时器，执行路径不变 |
| 定时任务会不会重复执行 | 每一步先在锁内标记为“执行中”再执行，同一服务同时只允许一个推进；有并发测试 |
| 安全怎么保证 | 页面不直接控制设备；Agent 不绕过执行器；确认幂等、单空间单服务、停止后旧计划失效 |

## 出问题时

| 现象 | 处理 |
|---|---|
| 提示“无法连接后端” | 检查平板和电脑在同一网络、后端地址正确；不会自动回退到模拟数据 |
| 模型很慢 | 切到“规则”模式继续讲，计划来源会显示为规则 |
| 自动播放太快 / 太慢 | 可以暂停，改用“快进到 …”逐步讲 |
| 状态乱了 | “我的”页点准备演示 |
