# 验收标准

统一标准：**演示可见、面试可答、代码可指。**

- 演示可见：能在 App 上操作并看到结果。
- 面试可答：能用三句话说清“解决什么、怎么做、结果如何”。
- 代码可指：能打开对应目录和测试说明。

模拟、规则、真实模型调用必须分开标注；空目录或预留接口不算完成。

## 第一批

| 步骤 | 通过条件 |
|---|---|
| 0 实施基线 | 新同学能看懂当前做什么、不做什么、从哪开始（README、architecture、acceptance、status） |
| 1 最小骨架 | 前端类型检查通过；后端健康检查测试通过；App 可启动（真机未验证需标注）；前后端可独立启动；后端地址可配置 |
| 2 数据契约 | 字段/状态/错误两端一致；类型可用命令重新生成；两个人物偏好不同；演示身份与真实认证明确区分 |
| 3 可点击原型 | 选人物 → 输入 → 计划 → 确认 → 设备状态 → 停止 可走通；切换人物计划不同；未确认前设备不变；显示“前端模拟模式” |
| 4 无模型后端链路 | 下列 7 项有自动化测试：① 创建计划不改设备 ② 确认后后端状态改变并可读回 ③ A/B 计划不同 ④ 重复确认不重复执行 ⑤ 停止后旧请求不再产生动作 ⑥ 非法人物/参数/过期计划被拒绝 ⑦ 后端断开时 App 明确反馈（前端逻辑测试或人工验证记录）；CI 含类型检查、契约一致性、后端测试 |

### 本轮明确不做（需用户单独授权）

| 项 | 不做的理由 |
|---|---|
| 多实例与真实部署 | 虚拟 Gateway 已验证拒绝过期 `serviceEpoch`；真实网关仍须实现同一契约，并根据硬件延迟设计 Redis 锁续租 |
| 真实后台调度器 | 当前是模拟时钟；替换前必须验证时区、漏触发与重复触发，属于独立一轮 |
| 真实设备 / 语音 / 传感器接入 | 三个协议已就位，但没有对端可联调；接入前不得改写为“已接入” |
| DeepSeek 多样本指标 | 开发环境访问不到 `api.deepseek.com`，需在用户 Mac 终端执行 |
| 真机验收 | 需要物理 iPad / 安卓平板 |

## 深度标准（够用即停）

| 模块 | 够用 | 不必做 |
|---|---|---|
| 服务闭环 | 完整、可靠 | — |
| Experience Agent | 一次真实调用、结构化输出、超时降级；歧义时给出澄清问题而不是猜一个计划 | 反复打磨提示词、通用多轮对话记忆 |
| Space Execution | 体验方案映射成两三种设备动作 | 复杂能力推理 |
| Harness | 白名单、参数范围、确认、停止、日志 | 预算控制、循环上限 |
| Memory | 种子偏好 + 按人物隔离读取 | 对话中自动学习、向量检索 |
| Energy | 一条可解释规则 | 在线接入 MATD3 |
| Adapter | 虚拟设备 | 真实厂商对接 |
