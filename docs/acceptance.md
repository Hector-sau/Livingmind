# 验收标准

统一标准：**演示可见、面试可答、代码可指。**

- 演示可见：能在 App 上操作并看到结果。
- 面试可答：能用三句话说清“解决什么、怎么做、结果如何”。
- 代码可指：能打开对应目录和测试说明。

模拟、规则、真实模型调用必须分开标注；空目录或预留接口不算完成。

## 第一批

| 步骤 | 通过条件 |
|---|---|
| 0 实施基线 | 新同学能看懂当前做什么、不做什么、从哪开始（README、architecture、acceptance、status） |
| 1 最小骨架 | 前端类型检查通过；后端健康检查测试通过；App 可启动（真机未验证需标注）；前后端可独立启动；后端地址可配置 |
| 2 数据契约 | 字段/状态/错误两端一致；类型可用命令重新生成；两个人物偏好不同；演示身份与真实认证明确区分 |
| 3 可点击原型 | 选人物 → 输入 → 计划 → 确认 → 设备状态 → 停止 可走通；切换人物计划不同；未确认前设备不变；显示“前端模拟模式” |
| 4 无模型后端链路 | 下列 7 项有自动化测试：① 创建计划不改设备 ② 确认后后端状态改变并可读回 ③ A/B 计划不同 ④ 重复确认不重复执行 ⑤ 停止后旧请求不再产生动作 ⑥ 非法人物/参数/过期计划被拒绝 ⑦ 后端断开时 App 明确反馈（前端逻辑测试或人工验证记录）；CI 含类型检查、契约一致性、后端测试 |

## 第一批与第二批之间

| 项 | 通过条件 |
|---|---|
| B 并发修正 | 设备写入在服务锁之外；停止请求在慢设备写入进行中仍能立即返回；已开始的动作完成、其余跳过；服务层与 HTTP 层各一个并发测试 |
| 评审修正 R1 | 偏离上限由后端强制并有测试；网页端到端脚本入库且可一条命令复现；App 计划超时随后端模型超时调整；兜底异常统一格式；PR 模板含 Mock 同步项 |

## 第二批（第一批验收后逐项进行）

| 顺序 | 达到即停 |
|---|---|
| ⑤ 最小 AI 证据 | Experience Agent 一次真实模型调用生成结构化计划；规则/模型可切换；提交到显示计划目标 8 秒内（待验证目标，不含确认与设备动作时间）；超时或输出非法回退规则并标注来源。**完成状态分两级**：接口与测试就绪 = 8 项测试通过；真实调用已验证 = `scripts/try_model.py` 在有密钥的机器上成功并记录延迟（已达成：2026-09-17，2035 ms） |
| ⑥ 一次事件调整 | 休息 → 事件 → 调整 → 停止；停止后再注入事件不执行 |
| ⑦ 整晚服务 | 同一服务贯穿整晚；定时任务不重复；停止取消剩余任务 |
| ⑧ 补齐模块 | 每个模块一条真实工作路径 + 输入输出 + 调用证据 |
| ⑨ 逐页迁移 | 一页完成、一页验收 |

## 深度标准（够用即停）

| 模块 | 够用 | 不必做 |
|---|---|---|
| 服务闭环 | 完整、可靠 | — |
| Experience Agent | 一次真实调用、结构化输出、超时降级 | 反复打磨提示词、多轮澄清 |
| Space Execution | 体验方案映射成两三种设备动作 | 复杂能力推理 |
| Harness | 白名单、参数范围、确认、停止、日志 | 预算控制、循环上限 |
| Memory | 种子偏好 + 按人物隔离读取 | 对话中自动学习、向量检索 |
| Energy | 一条可解释规则 | 在线接入 MATD3 |
| Adapter | 虚拟设备 | 真实厂商对接 |
